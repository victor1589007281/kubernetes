## 概述

### 背景

在 Kubernetes 集群中，MySQL 等数据库服务通常需要预留大量内存（如 buffer pool），但实际使用率往往远低于预留值。基于 Linux 内核的**缺页中断（Page Fault）** 机制，内存只在真正访问时才会实际分配物理页面，这为内存超售提供了理论基础。

### 目标

1. **预测 MySQL 内存使用**：基于历史数据预测未来 3 天的内存使用量
2. **实现内存超售**：在不与 k8s 原有内存管理冲突的前提下，通过 cgroup 实现内存超售
3. **监控与告警**：当实际内存使用接近物理内存时，自动调整超售比例

### 算法详细设计

#### 1. 数据预处理

```go
// 处理 Buffer Pool 变更
func adjustForBufferPoolChange(dataPoints []DataPoint) []DataPoint {
    // 当 Buffer Pool 设置变化时，需要调整历史数据的权重
    // 使用 usage_ratio = actual_memory / buffer_pool 作为归一化指标
    // 这样可以消除 Buffer Pool 变化的影响
}
```

**核心思路**：使用 `usage_ratio = RSS / BufferPool` 作为预测指标，而非绝对内存值。这样当 Buffer Pool 设置变化时，历史数据仍然有效。

#### 2. Holt-Winters 三次指数平滑

适用于具有趋势和季节性的时间序列：

```
Level:    L_t = α(Y_t - S_{t-s}) + (1-α)(L_{t-1} + T_{t-1})
Trend:    T_t = β(L_t - L_{t-1}) + (1-β)T_{t-1}
Season:   S_t = γ(Y_t - L_t) + (1-γ)S_{t-s}
Forecast: F_{t+h} = L_t + h*T_t + S_{t+h-s}

其中:
  α = 数据平滑系数 (0.2-0.5)
  β = 趋势平滑系数 (0.1-0.3)
  γ = 季节性平滑系数 (0.1-0.3)
  s = 季节周期 (24小时 = 每日周期)
```

#### 3. 趋势分析移动平均

```
MA_t = (1/n) * Σ(Y_{t-i}), i = 0 to n-1

Trend = (MA_t - MA_{t-k}) / k

其中:
  n = 窗口大小 (推荐24，即一天)
  k = 趋势计算周期 (推荐72，即3天)
```

#### 4. 加权融合

```
Final_Prediction = w1 * HoltWinters + w2 * TrendMA + BufferPoolAdjustment

其中:
  w1 = 0.6 (短期权重)
  w2 = 0.4 (趋势权重)
  BufferPoolAdjustment = 当 Buffer Pool 变化时的调整因子
```

## 超售管理器

### 设计原则

1. **不与 k8s 原有内存管理冲突**：在 kubelet 的 cgroup 层级之上创建 logical memory 层
2. **基于预测设置超售比例**：根据预测的最大使用量计算安全的超售比例
3. **支持动态调整**：可以根据实时监控数据调整超售比例

### 超售比例计算

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         超售比例计算公式                                 │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│   基础公式:                                                              │
│   ┌───────────────────────────────────────────────────────────────┐     │
│   │                                                                │     │
│   │   oversell_ratio = total_buffer_pool / predicted_max_usage    │     │
│   │                                                                │     │
│   │   logical_memory = physical_memory * oversell_ratio           │     │
│   │                                                                │     │
│   └───────────────────────────────────────────────────────────────┘     │
│                                                                          │
│   安全边界:                                                              │
│   ┌───────────────────────────────────────────────────────────────┐     │
│   │                                                                │     │
│   │   safe_ratio = oversell_ratio * safety_factor                 │     │
│   │                                                                │     │
│   │   其中 safety_factor = 0.85 (预留 15% 安全边界)               │     │
│   │                                                                │     │
│   │   最终: max_oversell_ratio = min(safe_ratio, 2.0)             │     │
│   │        (限制最大超售比例为 2.0)                                │     │
│   │                                                                │     │
│   └───────────────────────────────────────────────────────────────┘     │
│                                                                          │
│   示例:                                                                  │
│   ┌───────────────────────────────────────────────────────────────┐     │
│   │   物理内存: 128GB                                              │     │
│   │   Pod1 Buffer Pool: 64GB, 预测最大使用: 25GB                   │     │
│   │   Pod2 Buffer Pool: 64GB, 预测最大使用: 30GB                   │     │
│   │                                                                │     │
│   │   总 Buffer Pool: 128GB                                        │     │
│   │   预测总最大使用: 55GB                                         │     │
│   │   oversell_ratio = 128 / 55 = 2.33                            │     │
│   │   safe_ratio = 2.33 * 0.85 = 1.98                             │     │
│   │   final_ratio = min(1.98, 2.0) = 1.98                         │     │
│   │                                                                │     │
│   │   logical_memory = 128GB * 1.98 = 253GB                       │     │
│   │   (可以部署更多 pod!)                                          │     │
│   └───────────────────────────────────────────────────────────────┘     │
│                                                                          │
└─────────────────────────────────────────────────────────────────────────┘
```
